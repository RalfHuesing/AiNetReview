# Roadmap: Structural duplication, reliable entry points, and readable Markdown reports

## Execution contract

The approved [concept](Konzept.md) is the sole product contract. Implement the unchecked items in order; resume at the first unchecked item. Each implementation item is one complete task slice: inspect the current code, implement its scope, add the required tests, update affected current-state documentation, verify, mark the item complete, and commit the explicit task paths. No separate milestone or leaf files are needed.

Before each implementation commit, run the build, FastTests, and normal IntegrationTests gates defined in [Build and Tests](../../docs/development/build-and-tests.md), plus `git diff --check`. Record the verification outcome in the completion response; do not mark an item complete on an unrun or failing required check. Documentation must describe only behavior that exists in that slice. Preserve unrelated changes and follow the [repository rules](../../.agents/rules/README.md).

The concept's non-goals apply to every item. There is no JSON finding export, new report format, measurement campaign, performance gate, comparative audit, or automatic refactoring. This roadmap does not start implementation. The final audit is read-only; the [workflow](../../.agents/agent-workflow/README.md) permits at most one subsequent correction task slice, performed by an implementation agent rather than the reviewer. The implementation orchestrator records and commits the final audit checkbox.
