# Current-state documentation

The host provides the `review [project-path]` and `baseline [project-path]` commands. Both use `ainetreview.json` in the selected project root and create it from the discovered solution when it is missing. The host initializes executable-relative Serilog file logging and composes configuration validation, solution loading, analysis execution, baseline handling, and Markdown publication. Its production registry contains `method-control-flow-outliers`, which reports methods that stand out in decision count or decision nesting within each C# project; `dead-code-candidates`, which reports possible unreferenced declarations; `duplicate-code-candidates`, which reports clusters of substantially similar method bodies across production and test C# projects; `structural-duplication-candidates`, which reports exact statement fragments after bound local/parameter normalization; `indirection-drift-candidates`, which reports qualifying current paths of statically bound transparent forwarding within production or test C# projects; `missing-test-evidence-candidates`, which reports structurally nontrivial production functions with no static test path or only an indirect path above its higher thresholds; `non-ascii-identifiers`, which reports declarations containing non-ASCII characters in production and test C# code; and `code-size-candidates`, which reports unusually large executable members, classes, and C# files across all C# project roles with measured sizes and selection reasons. Size and control-flow analyses support project-specific test thresholds through `testOptions`; duplicate, structural-duplication, forwarding, identifier, and dead-code analyses include test code; missing-test-evidence retains production functions as its candidate scope. The test-path analysis does not claim runtime coverage and uses snapshot-wide selection in `changed-files`: without a baseline it shows all its findings, and with a baseline it shows all or none depending on whether any C# snapshot path changed. Structural fragments retain file-based selection and include every occurrence in their dedicated report branch. Other analyses retain file-based selection. The repository-root `ainetreview.json` lists every production analysis; individual projects can disable a listed analysis with `enabled: false`. Each review atomically publishes the root index, six production/tests/mixed area indexes, and two `audit-map/{changed-files,all-findings}/index.md` views with compact package reports; original finding reports retain direct stable-ID anchors. Package reports link assigned findings, source locations, test context, and directly related packages. The root index contains the shared review guidance and links both audit-map views. The `all-findings` audit map is reference-only and requires an explicit full-audit request. The root index also shows project roles and classification reasons, enabled and inactive analyses, test applicability and option provenance, and broad scope exclusions even when there are no findings. Core also provides project path boundaries, Git-independent `.sln`/`.slnx` loading with materialized source text and compilation checks, a stateless analysis runner, and a Markdown report writer that preserves older runs.
