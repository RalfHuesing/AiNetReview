# Current-state documentation

The host provides the `review [project-path]` and `baseline [project-path]` commands. Both use `ainetreview.json` in the selected project root and create it from the discovered solution when it is missing. The host initializes executable-relative Serilog file logging and composes configuration validation, solution loading, analysis execution, baseline handling, and Markdown publication. Its production registry contains `method-control-flow-outliers`, which reports methods that stand out in decision count or decision nesting within each C# project; `dead-code-candidates`, which reports possible unreferenced declarations; `duplicate-code-candidates`, which reports clusters of substantially similar method bodies across production and test C# projects; `structural-duplication-candidates`, which reports exact statement fragments after bound local/parameter normalization; `indirection-drift-candidates`, which reports qualifying current paths of statically bound transparent forwarding within production or test C# projects; `missing-test-evidence-candidates`, which reports structurally nontrivial production functions with no static test path or only an indirect path above its higher thresholds; `non-ascii-identifiers`, which reports declarations containing non-ASCII characters in production and test C# code; and `code-size-candidates`, which reports unusually large executable members, classes, and C# files across all C# project roles with measured sizes and selection reasons. Size and control-flow analyses support project-specific test thresholds through `testOptions`; duplicate, structural-duplication, forwarding, identifier, and dead-code analyses include test code; missing-test-evidence retains production functions as its candidate scope. The test-path analysis does not claim runtime coverage and uses snapshot-wide selection in `changed-files` when a baseline exists: it shows all or none depending on whether any C# snapshot path changed. Structural fragments retain file-based selection and include every occurrence in their dedicated report branch. Other analyses retain file-based selection. The repository-root `ainetreview.json` lists every production analysis; individual projects can disable a listed analysis with `enabled: false`. Each review atomically publishes the root index and the complete `all-findings` area indexes and compact map. When a baseline exists, the selected `changed-files` area indexes and map are also published. Each map groups findings by project and source file, preserves stable finding IDs and occurrence roles/locations, and links directly to original finding reports for full analysis evidence. Without a baseline, `all-findings` is the ordinary audit scope; with a baseline it requires an explicit full-audit request. The root index also shows project roles and classification reasons, enabled and inactive analyses, test applicability and option provenance, and broad scope exclusions even when there are no findings. Core also provides project path boundaries, Git-independent `.sln`/`.slnx` loading with materialized source text and compilation checks, a stateless analysis runner, and a Markdown report writer that preserves older runs. See [Current findings](review/findings.md) for the audit-map and finding-report contract.
