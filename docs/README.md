# Current-state documentation

The host provides the `review [project-path]` and `baseline [project-path]` commands. Both use `ainetreview.json` in the selected project root and create it from the discovered solution when it is missing. The host initializes executable-relative Serilog file logging and composes configuration validation, solution loading, analysis execution, baseline handling, and Markdown publication. Its production registry contains `method-control-flow-outliers`, which reports methods that stand out in decision count or decision nesting within each C# project; `dead-code-candidates`, which reports possible unreferenced declarations; `duplicate-code-candidates`, which reports clusters of substantially similar method bodies across production and test C# projects; `structural-duplication-candidates`, which reports exact statement fragments after bound local/parameter normalization; `indirection-drift-candidates`, which reports qualifying current paths of statically bound transparent forwarding within production or test C# projects; `missing-test-evidence-candidates`, which reports structurally nontrivial production functions with no static test path or only an indirect path above its higher thresholds; `non-ascii-identifiers`, which reports declarations containing non-ASCII characters in production and test C# code; `code-size-candidates`, which reports unusually large executable members, classes, and C# files across all C# project roles with measured sizes and selection reasons; `type-dependency-cycle-candidates`, which reports maximal production type components meeting the three-type and three-declaration-file floors with internal edge witnesses; and `type-dependency-hub-candidates`, which reports production types whose distinct direct production fan-in and fan-out both meet configurable inclusive thresholds of 10 by default, with complete neighbors and separate test-consumer context. Size and control-flow analyses support project-specific test thresholds through `testOptions`; duplicate, structural-duplication, forwarding, identifier, and dead-code analyses include test code; missing-test-evidence, cycle, and hub findings use production subjects. Missing-test-evidence, type-dependency-cycle, and type-dependency-hub findings use snapshot-wide selection in `changed-files` when a baseline exists: they show all or none depending on whether any C# snapshot path changed. Structural fragments retain file-based selection and include every occurrence in their dedicated report branch. Other analyses retain file-based selection. The repository-root `ainetreview.json` lists every production analysis; individual projects can disable a listed analysis with `enabled: false`. Each review atomically publishes the root index, area indexes, and an audit map for each available view. Maps group by project and representative source file, then list each canonical report path once with all routed finding IDs. Without a baseline, `all-findings` is the ordinary audit scope; with a baseline it requires an explicit full-audit request. The root index shows project roles and classification reasons, analysis enabled state and subject scope, effective options, and broad scope exclusions even when there are no findings. Core also provides project path boundaries, Git-independent `.sln`/`.slnx` loading with materialized source text and compilation checks, a stateless analysis runner, and a Markdown report writer that preserves older runs. See [Current findings](review/findings.md) for the audit-map and finding-report contract.
